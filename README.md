# FoodDK

منصة توصيل طعام للدنمارك، تربط الزبائن والمطاعم والسائقين.

## المرحلة الأولى (الحالية)
- تسجيل دخول وإنشاء حساب للزبائن
- قائمة المطاعم والقوائم والسلة
- إتمام الطلب مع حساب الأسعار على الخادم وفق الضريبة الدنماركية (moms 25%)
- لوحة المطعم: قبول الطلب، بدء التحضير، جاهز للاستلام
- لوحة السائق: استلام المهمة، الاستلام، التسليم
- تتبع حالة الطلب للزبون

**ملاحظة:** الدفع في هذه المرحلة تجريبي فقط. الدفع الحقيقي عبر Stripe في المرحلة الثانية.

## التقنيات
- Next.js (App Router) + TypeScript + Tailwind
- قاعدة بيانات SQLite عبر `node:sqlite` (محلياً، في مجلد `data/`)
- كلمات المرور مشفّرة بـ scrypt

## التشغيل المحلي
متطلبات: Node.js 22.13 أو أحدث.
```
npm install
npm run dev
```
افتح http://localhost:3000

## المرحلة الثانية: الدفع (Stripe)

الدفع يُفعَّل عند إعداد المتغيرات التالية. بدونها يعمل التطبيق في الوضع التجريبي.

| المتغير | الوصف |
|---|---|
| `STRIPE_SECRET_KEY` | مفتاح Stripe السري (يبدأ بـ `sk_test_` في وضع التجربة) |
| `STRIPE_WEBHOOK_SECRET` | سر التحقق من الـ webhook (يبدأ بـ `whsec_`) |
| `APP_URL` | العنوان العام للتطبيق، مثلاً `https://fooddk.example` |
| `PLATFORM_FEE_PERCENT` | عمولة المنصة من كل طلب، الافتراضي 10 |

**إعداد الـ webhook:** أضف endpoint بالعنوان `APP_URL/api/webhooks/stripe` واختر الأحداث
`checkout.session.completed` و`checkout.session.expired`.

**توزيع الأموال على المطاعم:** كل مطعم يحتاج حساب Stripe Connect، ويُخزَّن معرّفه في
عمود `stripe_account_id` بجدول المطاعم. بدون هذا المعرّف تبقى الأموال عند المنصة.

**ملاحظات:**
- الطلب لا يصل للمطعم قبل تأكيد الدفع عبر الـ webhook.
- عند رفض الطلب أو إلغائه بعد الدفع يُسترجع المبلغ تلقائياً.
- تحديث حالة الطلب بالـ webhook مكرر الاستدعاء آمن.
